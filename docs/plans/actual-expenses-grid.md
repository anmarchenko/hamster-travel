# Actual expenses as a compact sheet

## Design

Use one small sheet under each budget category. Keep the category estimate and Food's per-day calculation above it. The existing grid stretches across the category, right-aligns amounts, and replaces an edited cell with a full-width form. The sheet stays on the left and keeps the rest of the cells in place during an edit.

- Start with four columns of about 100–112 px and 28 px rows on desktop. Use left-aligned tabular figures, a thin grid, muted `A–D` and `1–n` headers, and an outline around the active cell. Keep the estimate separately labeled. Use two columns and at least 44 px touch targets on narrow screens. Freeze the column count while a cell is being edited or a paste is pending.
- Fill cells left to right, oldest first. The next free cell is `+`. Saving a new expense moves focus to the next free cell for continuous entry. Keep a visible add action and an amount/currency editor reachable by tap and keyboard, including when there are no expenses yet.
- Show the current display currency and mark converted values. Selecting a converted cell reveals its original amount and currency. Its inline editor opens in the original currency. Currency changes and deletion are explicit actions in the expense editor.
- Click to select. Use arrows to navigate, Shift+arrows or dragging to select a rectangle, and double-click or F2 to edit in place. Typing a digit starts a replacement. Enter commits and moves down, Tab commits and moves right, and Escape cancels. Tab can leave the grid at its boundary.
- Copy a rectangle as tab-separated displayed numeric values in the grid's labeled currency. Paste a rectangle onto existing cells starting at the top left of the selection. Bare amounts can overwrite cells whose original currency matches the displayed currency. At `+`, paste appends amounts in reading order, with the input currency stated before saving. If the display and trip currencies differ, show the paste currency and let the user select it before committing. Blank clipboard entries are skipped. An invalid amount, out-of-range target, or incompatible currency rejects the entire paste and identifies the offending cell.

Two other layouts are worth comparing in the first browser pass. A compact grid without headers leaves the most room for amounts, but makes ranges and validation errors harder to identify. A ledger with one expense per row and separate Amount and Currency columns makes mixed-currency entries easier to scan, but uses 19 rows for the screenshot's 19 expenses. Start with the compact sheet with headers.

## Library choice

**Implementation decision.** The RevoGrid 4.31.4 spike bundled with esbuild, but its paste event receives values after the grid clips them to the visible cells. The expense sheet needs the whole clipboard block to reject out-of-range pastes and append at `+`. Jspreadsheet CE also constrains clipboard customization. The implementation uses a native table with a lazy LiveView hook, keeping the expense-specific behavior and existing edit forms in the app.

- **Spike RevoGrid core first.** The MIT-licensed Web Component fits the existing JavaScript hooks without a framework. Its documented keyboard, rectangular selection, clipboard, and cancellable edit events cover most of the interaction. Check that narrow, auto-height sheets can be styled to match the mockup and that F2 and Enter commit movement can be matched with small customizations. [Core repository](https://github.com/revolist/revogrid) · [Keyboard](https://rv-grid.com/guide/keyboard) · [Clipboard](https://rv-grid.com/guide/clipboard) · [Editing](https://rv-grid.com/guide/editing)
- **Keep Jspreadsheet CE v5 as the fallback.** It is MIT-licensed vanilla JavaScript with worksheet headers, selection, paste interception, and built-in history. CE's copy event cannot rewrite clipboard values, so verify that a numeric cell renderer can keep localized display separate from the copied value. Disable formula evaluation and unrelated spreadsheet actions for money cells. [CE repository](https://github.com/jspreadsheet/ce) · [CE clipboard docs](https://bossanova.uk/jspreadsheet/docs/clipboard) · [CE events](https://bossanova.uk/jspreadsheet/docs/events)
- **Handsontable is a licensed option.** It documents extensive keyboard controls and accessibility support. Its deployment terms are a separate decision. AG Grid places rectangular selection and spreadsheet clipboard features in Enterprise. [Handsontable keyboard shortcuts](https://handsontable.com/docs/javascript-data-grid/keyboard-shortcuts/) · [Handsontable license](https://handsontable.com/docs/javascript-data-grid/license-key/) · [AG Grid clipboard](https://www.ag-grid.com/javascript-data-grid/clipboard/)

## Implementation

1. **Run a library spike on the Budget tab.** Mount two category sheets through the existing lazy-hook setup. Use sample EUR and foreign-currency expenses. Verify that the grid can handle keyboard and pointer interactions independently in both categories, work in light and dark themes, and avoid internal scrolling for short lists. Check the bundled asset size, English and Russian localization, keyboard focus, screen reader behavior, and Chrome, Firefox, and Safari clipboard support. Adopt the library if this works without patching it or reimplementing most of its focus and clipboard behavior.
2. **Wire up single-cell editing.** Keep `BudgetCategory` as the LiveView boundary. Let the hook own the grid DOM in a small `phx-update="ignore"` subtree, with authoritative snapshots supplied by the server. Each occupied cell carries an expense ID, canonical amount and currency, and a formatted display value. Reuse the existing Planning writes, money formatting, and edit authorization. Reconcile PubSub updates by expense ID so other users' changes and currency switches preserve selection and active drafts where possible. Reject stale saves, report the current value, and keep the draft available. Visitors and disconnected clients can view the last loaded amounts. Preserve the existing add/edit form as the touch and fallback editor until the inline equivalent passes the same checks. [LiveView JavaScript interoperability](https://hexdocs.pm/phoenix_live_view/js-interop.html)
3. **Add transactional range paste.** Parse and bound the clipboard payload before writing. Use one Planning call and one transaction for the category, with permission and category ownership checks, validation against the original currency, and stale-value checks by expense ID. Serialize overlapping category writes, including single edits, so automatic estimate raises see a consistent actual sum. Reuse the same changeset and estimate rules, calculate from the final batch, and broadcast one refresh after commit. Preserve clipboard order for appends and avoid replaying a paste automatically after reconnect. The server returns the new snapshot or the failing cell. Disable library-local undo for saved edits until there is a server-backed inverse operation.
4. **Verify the workflow.** Extend the existing Planning and LiveView tests for permissions, positive amounts, foreign currency, atomic rollback, order, estimate behavior, and two editors changing the same cell. Exercise focus after LiveView patches, rapid consecutive adds, mixed-currency paste, and reconnect in the browser suite. Check clipboard interoperability with Excel in addition to testing the web events. Run `mix format`, `mix test`, `mix credo --strict`, and the browser checks before shipping.

The first release covers the Excel motions that matter for entering expenses. Formulas, fill handles, arbitrary row or column changes, and workbook import stay outside that release. Server-backed undo can follow once the edit and paste commands have stable identities and conflict handling.
